# Local Broadcast 0.3.9-beta.2

В настройках захвата можно выбрать GStreamer. При первом запуске GStreamer после малого обновления приложение подготовит Windows runtime (около 85 МиБ загрузки). Полный Offline-пакет содержит runtime для установки без сети. В автоматическом режиме для экрана с системным звуком и фиксированным FPS используется GStreamer. Для камер, адаптивного FPS и общего рабочего стола из нескольких мониторов используется FFmpeg. Движок можно выбрать вручную.

[Журнал исследования пропусков звука: результаты, экспериментальный код и план проверки](docs/AUDIO_RESEARCH_LOG.md)

В 0.3.7-beta.1 исправлены микропропуски системного звука WASAPI. Для проверки исправления обновите прежде всего презентер. Задержка видео более секунды в OBS ещё не устранена; результаты испытаний — [в отчёте](docs/DIAGNOSTICS_2026-11-19.md).

Если аппаратный кодировщик QSV/NVENC/AMF не запускается, начиная с 0.3.7-beta.3 программа при распознанной ошибке переключает текущую передачу на CPU — x264. Выбранный и используемый кодировщики показаны в настройках; нагрузка на CPU может вырасти. В предыдущих версиях выберите CPU — x264 вручную и сохраните настройки.

В 0.3.8-beta.1 исправлена тишина в длительной передаче WASAPI: в локальный канал к FFmpeg добавлены явные метки времени PCM. Обновите прежде всего презентер; сетевой формат и настройки не изменены.

## Экран и источник звука

На **ПК-презентере** откройте **Настройки → Видео и звук → Обновить экраны и источники звука**. В «Какой экран передавать» выберите монитор или весь рабочий стол. В режиме WASAPI выберите аудиовыход, через который слышно нужное приложение: колонки, HDMI-монитор или наушники. Для микрофона выберите режим DirectShow и его имя из подсказок. Нажмите **Сохранить настройки**; захват перезапустится автоматически.

В том же разделе доступны **размер отправляемого изображения** (480p/720p/1080p) и **FPS** (15/30/60/адаптивный 15–30). Для первого сравнения нагрузки на слабом приёмнике выберите **720p и 15 FPS**. Пропорции сохраняются; портретный или широкий рабочий стол дополняется полями до выбранного размера.

Адаптивный режим захватывает с целевой частотой 30 FPS и убирает часть почти одинаковых кадров, приближаясь к 15 FPS на статичном экране и к 30 при движении. Он сохраняет исходные временные метки, звук не перезапускается при смене активности изображения. Это не адаптация по сети/нагрузке приёмника. Фактический FPS зависит от возможностей захвата и ПК. Ручное сохранение нового разрешения/FPS кратко перезапускает передачу.

Пункт «Устройство Windows по умолчанию» следует смене системного выхода. Явный выбор остаётся закреплённым за конкретным устройством. Если приложение выводит звук на другой выход, выбранный источник может передавать тишину. Настройки на главном ПК не управляют выбором устройства на презентере.

При отключении/перенастройке аудиоустройства захват автоматически переоткрывается; этап восстановления виден в журнале. Для недоступного выбранного монитора нужно обновить список и выбрать доступный экран.

## Управление без браузера

При обычном запуске открывается отдельное окно **«Local Broadcast — управление»** со статусом и журналом. Кнопки **«Перезапустить»** и **«Завершить»** управляют программой напрямую, браузер для этого не требуется. Кнопка **«Панель в браузере»** открывает расширенные настройки.

Крестик скрывает окно в системный трей возле часов. Нажмите на значок **LB**, чтобы открыть окно; правой кнопкой доступно меню перезапуска и завершения. Значок может находиться под стрелкой скрытых значков Windows. Повторный запуск EXE или ярлыка открывает уже работающую программу. Автозапуск Windows работает в фоне, без открытия браузера; `-no-browser` также включает фоновый запуск.

## Скачать на другой компьютер

Откройте [GitHub Releases](https://github.com/bukirev/LocalBroadcast/releases) и скачайте **`LocalBroadcast-0.3.9-beta.2-Setup.exe`**. Запустите файл, выберите роль компьютера и нажмите **«Установить и запустить»**. На клиентском ПК вставьте общий ключ из настроек главного компьютера. Установщик запросит разрешение Windows для системной настройки.

Установщик автоматически:

- скачивает FFmpeg/FFplay с поддержкой SRT и проверяет SHA256;
- на главном ПК устанавливает OBS Studio и Microsoft Visual C++ Runtime, если совместимый OBS ещё не найден;
- включает OBS WebSocket, создаёт пароль и сохраняет его в LocalBroadcast; существующие порт и пароль сохраняются;
- настраивает правила брандмауэра для Private/LocalSubnet; при выбранной опции переводит подключённые физические Ethernet/Wi-Fi сети из Public в Private;
- сохраняет роль и пути, создаёт ярлыки на рабочем столе и в меню «Пуск», включает выбранный автозапуск;
- выбирает единственную камеру автоматически или предлагает выбор из нескольких;
- запускает программу и открывает окно управления Windows. Расширенные настройки доступны по кнопке «Панель в браузере».

Обычному установщику нужен интернет. FFmpeg загружается с официального GitHub-зеркала, gyan.dev используется как запасной источник. В консоли видны проценты, объём и скорость. Подключение ограничено 20 секундами, простой передачи — 30 секундами, одна попытка — 15 минутами. После ошибки выполняется переход к следующему источнику; каждый файл проверяется по SHA256.

Приложение устанавливается в профиль исходного пользователя; только системные компоненты и брандмауэр настраиваются с повышенными правами. При обновлении LocalBroadcast закрывается, а перед настройкой OBS установщик просит закрыть работающий OBS. Настройки и идентификаторы устройств сохраняются; конфигурации резервируются. Публичный эфир запускается оператором в OBS вручную.

Альтернатива: скачайте ZIP, распакуйте и запустите **`Install.cmd`** — это тот же мастер. Прямой запуск EXE из ZIP остаётся переносимым вариантом с ручной установкой зависимостей.

Журнал установки: `%LOCALAPPDATA%\LocalBroadcast\Downloads\install.log`. Повторный запуск использует проверенные загрузки из кеша. Обнаружение устройств и общая задержка всё ещё требуют проверки на ваших ПК.

## Установка без загрузок на другом ПК

На компьютере с работающим интернетом распакуйте обычный ZIP релиза и запустите **`Prepare-Offline.cmd`**. Скрипт скачает оригинальные архивы FFmpeg, OBS и Microsoft Runtime с сайтов разработчиков, проверит SHA256 и создаст рядом **`LocalBroadcast-0.3.9-beta.2-Offline.zip`** (около 330 МБ).

Перенесите этот архив на другой ПК, распакуйте и запустите **`Install.cmd`**. Компоненты будут взяты из папки `dependencies`; обращения к серверам загрузки не нужны. Общий ключ с главного ПК по-прежнему требуется на клиентах. Сам архив нельзя запускать без распаковки.

Для текущих старых установщиков можно вручную положить оригинальный архив FFmpeg под именем `ffmpeg-9.0.2.zip` в `%LOCALAPPDATA%\LocalBroadcast\Downloads` и повторить установку. Если предыдущая загрузка ещё работает, сначала завершите её через Ctrl+C.

**Единая Windows-программа с главным OBS Studio, презентером и 1–3 камерными/просмотровыми компьютерами.** Передаёт экран, системный звук и камеры в локальной сети. Предусмотрены **UDP**, **SRT с восстановлением потерь**, нативный **Windows WASAPI Loopback**, настройка синхронизации потоков в OBS и автоматический запуск.

> **Это тестовая сборка, не проверенная на реальном Windows-оборудовании.** Исходники, тесты и Windows x64 exe собраны; реальный Windows WASAPI, физические камеры, OBS и Wi-Fi требуют приёмочных испытаний. Не использовать без проверки в ответственном прямом эфире.

## Переносимый запуск без установщика (Windows 10/11 x64)

1. Скопируйте `LocalBroadcast.exe`, `ffmpeg.exe`, `ffplay.exe` на каждый ПК. FFmpeg/FFplay в этот ZIP **не входят**: [официальная страница](https://ffmpeg.org/download.html). Для режима SRT нужна сборка FFmpeg с включённой библиотекой `libsrt` (`ffmpeg -protocols`, в выводе должна присутствовать `srt`).
2. На главном ПК установите OBS Studio 28+ и включите WebSocket в меню «Инструменты»; запомните пароль и порт (стандартно 4455). Главный ПК желательно подключить Ethernet-кабелем к роутеру.
3. Запустите `LocalBroadcast.exe` на **главном ПК** и нажмите «Панель в браузере». В панели `http://127.0.0.1:39888` выберите роль **Главный OBS**, заполните пароль OBS, общий ключ и выберите транспорт **SRT** (рекомендуется для Wi-Fi) или **UDP** (ниже задержка при идеальной сети). Сохраните и нажмите «Перезапустить программу» в появившемся уведомлении. Панель подключится снова автоматически.
4. На **презентере** запустите ту же программу, выберите **Презентер: экран и звук**. Установите `WASAPI` для звука Windows; источник — **устройство вывода по умолчанию Windows**. Скопируйте общий ключ с главного ПК, сохраните.
5. На **камерных ПК** выберите роли «Камера» либо «Камера + экран». В разделе **Устройства** получите точное DirectShow-имя камеры и внесите в настройки. Используйте 1280×720/30 FPS как базовый режим.
6. На главном ПК в **OBS Studio** нажмите **Синхронизировать источники OBS**. Программа создаст Media Source в отдельной сцене `Local Broadcast`. Камеры размещаются и масштабируются в OBS оператором. Выход в интернет запускается в OBS **вручную**.
7. Если устройства не обнаруживаются, укажите клиентам IPv4 главного ПК и запустите `configure-firewall.ps1` от администратора на нужных машинах. Правила открыты **только для частной сети** и источников LocalSubnet.

### Локальные порты

| Канал | UDP unicast | SRT между ПК | На ПК OBS |
|---|---|---|---|
| Экран + системный звук | `5000` | `11000` | Media Source `udp://0.0.0.0:5000` |
| Камера 1 | `5101` | `11101` | Media Source `udp://0.0.0.0:5101` |
| Камера 2 | `5102` | `11102` | Media Source `udp://0.0.0.0:5102` |
| Координатор | `39780/TCP` | — | управление и маршруты |
| Обнаружение | `39721/UDP` | — | LAN broadcast |
| Локальная панель | `127.0.0.1:39888/TCP` | — | не открывать в сеть |

При SRT получатель слушает входящий SRT и локально переводит его в UDP для OBS или FFplay — **OBS не нужно вручную перенастраивать при выборе транспорта**. Каждый SRT-поток передаётся отдельным FFmpeg-ретранслятором без повторного кодирования H.264/AAC; одно кодирование и несколько получателей сохраняются.

### Настройки задержки и надёжности

- **UDP** — минимальная буферизация, нет восстановления потерянных UDP-пакетов; на Wi-Fi возможны артефакты.
- **SRT** — ARQ (повторная отправка пропавших пакетов), шифрование SRT с общим ключом, повторное подключение, начальная задержка **180 мс**. Для нестабильной Wi-Fi сети начните с **200–300 мс**. Это параметр *SRT*, не общая задержка от камеры до OBS.
- **Адаптация SRT** — во время повторных коротких разрывов повышает буфер следующего подключения на 40 мс, максимум до 600 мс; после продолжительной стабильности при следующем переподключении может постепенно его снижать. В течение активного стабильного сеанса буфер не меняется; собственное восстановление пакетов выполняет SRT. **Это не полноценный мгновенный ABR/битрейт-адаптер.**
- Если Wi-Fi перегружен, уменьшите битрейт камеры до 1,5–2,5 Мбит/с. Используйте 5/6 ГГц. Тестируйте при включённых нескольких камерах.

### Нативное аудио WASAPI

`LocalBroadcast.exe` на Windows использует COM-интерфейсы `IMMDeviceEnumerator` + `IAudioClient` + `IAudioCaptureClient` для loopback-захвата выходного микса по умолчанию. PCM поступает в FFmpeg по stdin, где кодируется в AAC 48 кГц с асинхронным resample. Никаких виртуальных устройств Stereo Mix не требуется. Если WASAPI недоступен, выберите режим **DirectShow** или **Без звука**. При смене основного устройства вывода Windows во время работы аудиозахват будет перезапущен.

**Ограничения WASAPI:** в этой версии используется только основной аудиовыход Windows, не произвольно выбранная звуковая карта; сторонние звуковые драйверы, HDMI/BT устройства и особые форматы потока требуют реальной проверки. Точный A/V lipsync на конкретном ПК пока не гарантирован.

### Синхронизация всех источников в OBS

На главном ПК откройте вкладку **Синхронизация**. Программа автоматически оценивает половину RTT до клиентов по контрольным HTTP-сообщениям и настраивает для каждого входа OBS фильтр **Render Delay** и соответствующее **Audio Sync Offset**. При необходимости впишите сохранённые поправки `Видео, мс` и `Звук, мс` отдельно для каждой камеры.

**Важное ограничение:** RTT/2 — оценка *сети*, а не полной задержки экспозиции камеры, USB, энкодера и OBS. Для точной автоматической синхронизации после запуска нужна **калибровка на реальном железе**: кадр со вспышкой и одновременно записанный хлопок / тестовый таймкод на всех камерах. В этой версии поправки можно сохранить и применять автоматически, но алгоритм компьютерного зрения для автоматической калибровки вспышки ещё не реализован.

### Монтаж и режимы

Все компьютеры используют **один и тот же EXE** и локальную веб-панель. Роли: OBS master, Presenter, Camera, Camera + Watch, Watch only, Custom. Главный OBS управляет маршрутизацией; отправитель передаёт UDP/SRT напрямую на конкретные ПК, не через сервер видео. Главный ПК не начинает публичную трансляцию самостоятельно.

## Разработчикам

Кодовая база: Go со стандартной библиотекой (Windows WASAPI через COM syscall), встроенные HTML/CSS/JavaScript, FFmpeg/FFplay и OBS WebSocket v5. На Windows сборка с `CGO_ENABLED=0`.

```powershell
# В папке исходного кода после установки Go:
go test ./...
.\scripts\build-windows.ps1
# dist\LocalBroadcast.exe
```

Реальный SRT-интеграционный тест на машине с FFmpeg/libsrt:

```bash
LB_TEST_MEDIA=1 go test -run TestSRT -v
```

Тест **выполнен в Linux loopback-сети**: один MPEG-TS передан по SRT в два разных получателя через независимые FFmpeg-процессы. Реальную WLAN-сеть, синхронизацию OBS и WASAPI после сборки нужно проверить в Windows.

Документы проекта: `docs/ARCHITECTURE.md`, `docs/PROTOCOL.md`, `docs/TEST_PLAN.md`, `docs/ROADMAP.md`.

## Ограничения и безопасность

- Сборка unsigned — Windows SmartScreen может запросить подтверждение; для широкого распространения необходима подпись.
- Сетевой HTTP канал управления v0.2 **не использует TLS**; общий ключ передаётся в заголовке только в доверенной LAN. SRT-медиа шифруется отдельным passphrase. Не открывайте порты в интернет.
- FFmpeg и FFplay не включены в архив. Их лицензии LGPL/GPL зависят от конкретной сборки.
- Реальная задержка **не гарантирована**: целевые 200–500 мс зависят от камеры, оборудования, Wi-Fi, SRT latency и OBS.
- При использовании Windows WASAPI без реальной проверки на пользовательских устройствах могут оставаться баги драйвера или COM-взаимодействия.
- Автоматическое точное выравнивание *физических* камер пока не завершено, на текущем этапе используется оценка сети плюс сохранённая калибровка.



## Обновления на других ПК (с 0.3.6-beta)

Один раз установите 0.3.6-beta или новее полным установщиком на каждом ПК. Затем в окне Windows нажмите **«Обновления»** либо откройте одноимённый раздел браузерной панели: **Проверить → Скачать → Установить и перезапустить**. Для тестирования выбирайте канал beta. Проверка и загрузка не прерывают сервис; установка — отдельное действие. При записи или эфире OBS сначала завершите их.

Небольшой Update ZIP содержит ядро программы, а не повторную загрузку OBS/FFmpeg. Роль, общий ключ, идентификатор ПК и маршруты сохраняются; другие ПК обновляются на каждом устройстве отдельно. Старые версии не получат новый updater без первой ручной установки.

Подробности, выпуск, восстановление и границы проверок: [docs/UPDATES.md](docs/UPDATES.md), [docs/UPDATES_TEST_LOG.md](docs/UPDATES_TEST_LOG.md).
