# Проверка декодирования OBS на главном ПК

`Test-OBSDecoder.ps1` работает с установленной Local Broadcast 0.3.6+ и OBS WebSocket 5. Не требует Python, модулей PowerShell или изменения настроек WebSocket. Параметры локального OBS и пароль читает из работающего Local Broadcast; пароль не выводится и в backup не сохраняется.

Запускать **на главном ПК**, где OBS принимает `LB | Presenter`. Презентер продолжает работать. Сам скрипт не измеряет сквозную задержку: для каждого варианта нужен одновременный снимок секундомеров источника и OBS, желательно 3–5 повторов после 10 секунд установившейся работы.

```powershell
# Только собрать сведения. Изменений и backup нет.
powershell -NoProfile -ExecutionPolicy Bypass -File .\Test-OBSDecoder.ps1 -Mode Inspect

# Проверить звук: mute/громкость/мониторинг/дорожки, активную сцену,
# состояние источника, привязки UDP:5000 и трёхсекундный уровень сигнала.
# Только чтение, пароль в вывод не включается.
powershell -NoProfile -ExecutionPolicy Bypass -File .\Test-OBSDecoder.ps1 -Mode InspectAudio

# Полностью переоткрыть сетевой UDP:5000 вход без смены его настроек.
# Краткий разрыв изображения/звука; при записи/эфире действие блокируется.
powershell -NoProfile -ExecutionPolicy Bypass -File .\Test-OBSDecoder.ps1 -Mode ReopenInput

# Перезапустить только медиавход, сохранив настройки и резервную копию.
# При активной записи/эфире перезапуск блокируется.
powershell -NoProfile -ExecutionPolicy Bypass -File .\Test-OBSDecoder.ps1 -Mode RestartInput

# Сохранить прежнее значение и включить аппаратное декодирование.
# Источник кратко перезапустится. При записи/эфире скрипт откажется менять настройки.
powershell -NoProfile -ExecutionPolicy Bypass -File .\Test-OBSDecoder.ps1 -Mode HardwareOn

# После повторного замера вернуть прежнее значение.
powershell -NoProfile -ExecutionPolicy Bypass -File .\Test-OBSDecoder.ps1 -Mode Restore
```

`Inspect` выводит версии, CPU, состояние SRT, `hardwareDecode`, буфер Media Source и статистику рендера OBS. Наличие `hardwareDecode=true` означает включённую настройку, а не доказательство, что конкретный GPU успешно использован: нужна проверка изображения и результата измерения. Если настройка уже true, HardwareOn не создаёт другого варианта декодирования; такой A/B-тест неинформативен.

`InspectAudio` нужно запускать при играющей музыке на презентере. `audio.meter.signalSeen` показывает ненулевой уровень выбранного источника за три секунды, а `sourceActive`, текущие Program/Preview и мониторинг помогают отличить отсутствие данных от неактивной сцены или выключенного прослушивания. Наличие нескольких `inputsOnUDP5000` требует проверки конкурирующих медиавходов. Эта диагностика не переключает сцены, не включает мониторинг и не снимает mute автоматически. Недоступные необязательные запросы отражаются полем error вместо остановки всей диагностики.

`RestartInput` — отдельное изменение: перезапускает только выбранный Media Source, проверяя отсутствие записи/эфира и роль главного ПК. Настройки, аппаратное декодирование и backup не меняются. Перезапуск иногда нужен после смены/перезапуска входного потока; это проверка восстановления, а не гарантированное исправление любого отсутствия звука.

Резервная копия сохраняется в `%LOCALAPPDATA%\LocalBroadcast\Diagnostics\obs-hw-decode-backup.json`. До успешного Restore повторный HardwareOn не перезапишет её. Restore проверяет ПК, URL WebSocket и UUID источника и восстанавливает только изменённое поле `hw_decode`, сохраняя другие настройки. Не удаляйте backup до восстановления. При сбое подключения настройка не меняется; проверьте, что OBS и Local Broadcast запущены на главном ПК.

Отдельные параметры `-ApiPort`, `-InputName`, `-BackupPath` предназначены для изолированных проверок. Число CPU/affinity, кодировщик, SRT и звук скрипт не меняет.

Проверка инструмента: Windows PowerShell 5.1, сервер-имитатор с настоящим WebSocket handshake и проверкой SHA256-аутентификации; Inspect без записи; backup до изменения; применение только одного поля через overlay; Restore; запрет повторного теста поверх backup; отказ при активной записи/эфире. На новом физическом главном ПК инструмент ещё не запускался.

Дополнительно проверены InspectAudio с событиями уровня звука и несколькими UDP-входами, отсутствие любых записей в этом режиме, RestartInput с единственной командой перезапуска и блокировка при активном выходе. HardwareOn/Restore повторно проверены после добавления новых режимов.

Исправление инструмента от 20 ноября: прежняя версия ошибочно читала и записывала `is_hw_decoding`. В OBS 32.1.1 действующее поле — `hw_decode`; старый HardwareOn не подтверждает включение аппаратного декодирования. Новый backup имеет другое имя и маркер settingKey; Restore отвергает старые копии, чтобы не применять недостоверное исходное значение к настоящей настройке.

`ReopenInput` повторно применяет только исходный URL через overlay. Для сетевого Media Source OBS 32.1.1 обновление настроек пересоздаёт media playback даже при неизменном URL; обычный RestartInput может повторно использовать прежний декодер. Переоткрытие нужно проверить после восстановления AAC на отправителе, но исправление звука на главном пока не подтверждено.

Основание: [OBS 32.1.1 Media Source](https://github.com/obsproject/obs-studio/blob/32.1.1/plugins/obs-ffmpeg/obs-ffmpeg-source.c), [обработчик SetInputSettings](https://github.com/obsproject/obs-websocket/blob/master/src/requesthandler/RequestHandler_Inputs.cpp).

После исправления имени поля повторно пройдены проверки со строгим имитатором: разрешены только hw_decode/input; события уровня только с UUID; ReopenInput применяет исходный URL и сохраняет остальные поля; HardwareOn/Restore восстанавливают настоящее поле; старый backup и активные выходы блокируются. Это проверка протокола и защит скрипта, не физического приёмника.
