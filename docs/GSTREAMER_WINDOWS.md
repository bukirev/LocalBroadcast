# Local Broadcast для проверки GStreamer на Windows x64

Закройте предыдущий экземпляр через «Завершить», распакуйте архив целиком и запустите LocalBroadcast.exe. Если на чистом ПК отсутствует Microsoft Visual C++ Runtime, запустите приложенный VC_redist.x64.exe. На главном ПК используется существующая установка OBS. Выберите «Настройки → Видео и звук → Медиадвижок захвата → GStreamer (испытания)», сохраните. В статусе экрана/камеры проверьте фактический движок. Список устройств показывает возможности Media Foundation. Выберите отдельный монитор при нескольких экранах и фиксированный FPS.

Видео и звук используют один GStreamer pipeline. D3D11 или Media Foundation → H.264, WASAPI loopback или выбранный DirectShow audio source → AAC, общий mpegtsmux → локальный вход маршрутизатора. Coordinator задаёт SRT либо UDP всем участникам. Параметры синхронизации независимых камер задаются существующими настройками OBS.

Для возврата выберите FFmpeg. Настройки прежней установки хранятся в профиле Windows, поэтому для сравнения лучше записать исходные значения. Продолжайте использовать обычный выпуск на рабочих местах до аппаратной приёмки. Копировать один EXE поверх установленного пакета для этого испытания не требуется.

Пакет включает полный runtime официального MSI GStreamer 1.26.10 MSVC x86_64 и сборку FFmpeg из setup/dependencies.json. Оригинальные плагины включают компоненты с разными лицензиями, в том числе x264. Для повторной сборки используйте scripts/package-gstreamer.py с проверенными исходными дистрибутивами, EXE и путём нового ZIP. Сведения по лицензиям отдельных элементов доступны через gst-inspect-1.0. [Дистрибутив GStreamer](https://gstreamer.freedesktop.org/data/pkg/windows/1.26.10/msvc/) · [исходники GStreamer](https://gitlab.freedesktop.org/gstreamer/gstreamer) · [сборка FFmpeg](https://github.com/GyanD/codexffmpeg/releases/tag/9.0.2).

При запуске захвата GStreamer приложение пробует Media Foundation H.264, затем программный x264. При повторных ошибках переходит на FFmpeg для этого источника. При исчезновении видеобуферов watchdog завершает pipeline для перезапуска. В API media.screen.audio доступны peakDB и возраст последнего сообщения об аудиобуфере в миллисекундах. Тихие буферы дают низкий уровень с продолжающимися обновлениями. Телеметрия отправителя не измеряет качество декодированного звука в OBS.

Набор физических проверок и критерии приведены в ACCEPTANCE.md. Аппаратный H.264 passthrough для USB пока отключён. Сопряжение звукового входа HDMI с видеоустройством требует выбора в настройках. Режим всего рабочего стола из нескольких мониторов и адаптивный FPS обслуживает резервный FFmpeg.
