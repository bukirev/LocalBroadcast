# Выбор источников и восстановление звука — 0.3.7-beta.2

## Подтверждённая остановка аудио

На обоих ПК работала 0.3.7-beta.1. Входящий MPEG-TS содержал объявление AAC в PMT, но за 8 секунд не содержал ни одного пакета аудио PID 257. Источник OBS не был заглушён, громкость 0 дБ, шкала показывала ноль. Перезапуск только Media Source не восстановил звук.

Пользователь предоставил строку презентера: `WASAPI: COM method 5: HRESULT 0x88890004`. Это `AUDCLNT_E_DEVICE_INVALIDATED`: устройство отключено или перенастроено. [Microsoft рекомендует освободить WASAPI-интерфейсы и заново открыть выбранное/текущее устройство](https://learn.microsoft.com/en-us/windows/win32/coreaudio/recovering-from-an-invalid-device-error).

В прежнем supervisor завершение PCM не завершало FFmpeg: видео продолжало кодироваться, аудио больше не поступало, процесс оставался «работающим». Это отдельная проблема от округления QPC, исправленного в beta.1.

В новой версии supervisor следит за завершением WASAPI timeline, завершает старый кодер и открывает захват заново. Повторные попытки ограничены существующим интервалом 1–8 с, завершение приложения отменяет ожидание. При выборе системного устройства по умолчанию раз в секунду проверяется его идентификатор; смена выхода также запускает переоткрытие.

Для временного восстановления на реальной установке был выключен/включён маршрут презентер → OBS. После этого появились 376 AAC TS-пакетов за следующий восьмисекундный захват. Декодированный PCM содержал тишину, хотя пользователь слышал музыку на презентере. Это подтверждает восстановление передачи аудиодорожки, но не правильный выбор аудиовыхода. Причина тишины после переоткрытия окончательно не подтверждена: явный выбор нужного выхода необходимо проверить на презентере. Маршрут снова включён, исходный UDP-вход OBS и автосинхронизация восстановлены.

## Новые настройки

- `screenMonitor`: стабильное имя дисплея Windows; пустое значение сохраняет захват всего рабочего стола. Список показывает разрешение и основной монитор. Координаты берутся в физических пикселях, поддержаны отрицательные позиции мониторов и смешанный DPI. Физическое тестирование второго монитора/смешанного DPI на текущем ПК не выполнено; отрицательные координаты проверены тестом аргументов.
- `screenAudioEndpoint`: ID активного устройства вывода WASAPI; пустое значение означает системный выход по умолчанию. Legacy `screenAudioDevice` остаётся для DirectShow. Выбор конкретного выхода не переключает Windows и не перенаправляет приложения: захватывается только микс этого выхода.
- В интерфейсе есть списки экранов и аудиовыходов, обновление списков и подсказки обнаруженных аудиовходов DirectShow. Сохранённый недоступный выбор остаётся виден; автоматическая подмена другим монитором/выходом не выполняется.
- При смене источника перезапускается экранный pipeline, камера не затрагивается. Обновление через EXE сохраняет настройки и зависимости. Старые конфигурации без новых полей сохраняют прежние значения по умолчанию.
- Журнал показывает имя открытого аудиоустройства, формат и восстановление захвата; API timeline показывает `closed`.

## Испытания

- Один и тот же `TestWASAPICaptureEOFRecoversLiveAudio` на опубликованных исходниках beta.1 воспроизводит дефект: после первого EOF AAC не возобновляется, тест завершается ошибкой.
- На исправлении: явный выбор реального основного монитора 2560×1440 и аудиовыхода HDMI, затем два принудительных завершения PCM. На начальном запуске и после каждого обрыва приняты как минимум 12 настоящих AAC TS-пакетов. В журнале ровно два события восстановления. Тест проходит за ~4,6 с. Это инъекция завершения capture, а не физическое отключение устройства.
- Реальный gdigrab + WASAPI: 60 кадров/4,000 с, AAC 4,032 с, разница начала 21,3 мс, lateFrames=0.
- Контрольный тон: все 75 измеренных окон содержат звук, 4 с PCM выданы за 4,032 с.
- Проверено сохранение ID экрана/аудиовыхода в конфигурации после перечитывания и изменение подписи только экранного pipeline.
- Проверено построение региона для экрана слева/выше основного и отказ при отключённом выбранном дисплее.
- В изолированном приложении без сетевых потоков проверены браузерные списки, выбор, сохранение, повторное обновление списка и внешний вид. Обнаружены один монитор и два реальных аудиовыхода. Известные прежние сообщения CSP inline style/favicon не относятся к новым контролам.
- `go test ./...`, `go vet -unsafeptr=false ./...`, `node --check assets/app.js` проходят. Исключение проверки unsafe.Pointer остаётся для Windows COM ABI, как и в предыдущей версии.

Не подтверждены: звук выбранного выхода на физическом презентере после обновления; реальное отключение/переключение устройства под длительной нагрузкой; захват второго монитора в смешанном DPI. Уменьшение задержки видео не входит в этот выпуск.
