# Local Broadcast 0.2 — план приёмочных испытаний

## Подготовка

Главный ПК с OBS + 1 презентер + 2 камерных Windows 10/11 ПК; выделенный Wi-Fi 5/6 GHz; FFmpeg/libsrt на всех узлах, доступ к маршрутизатору; OBS WebSocket 5.

## 1. Системный звук Windows / WASAPI

1. На презентере выбрать `WASAPI`, включить воспроизведение тестового звука в браузере; OBS должен принимать AAC вместе с экраном.
2. Проверить паузу 30 секунд и возобновление звука — после тишины дорожка не должна зависать.
3. Проверить 44,1 / 48 kHz вывод, наушники / HDMI / USB-колонки / Bluetooth (по возможности).
4. Сменить устройство вывода Windows во время трансляции; система должна сообщить ошибку и восстановиться при следующем запуске захвата.
5. Проверить, что FFmpeg не падает при тишине и что в конце потока нет бесконечного зависания stdin.

## 2. SRT / Wi-Fi

1. Начать с 180–250 мс latency, камеры 720p/30 по 2,5 Мбит/с, экран 1080p/30 6 Мбит/с.
2. Одновременная передача экрана на OBS и 2 ПК; обе камеры на OBS (3+ параллельных видеонаправления).
3. Отключить одну камеру от Wi-Fi на 3–5 секунд и вернуть, измерить время восстановления и отсутствие вмешательства в другие потоки.
4. Имитировать 1–3% потерь пакетов и померить число зависаний/артефактов. В Windows можно использовать подходящий сетевой эмулятор; не применять имитацию на реальном эфире.
5. Подтвердить повышение effective SRT latency при повторных обрывах; проверить, что SRT Passphrase одинаков на всех ПК.
6. Переключить главный OBS с SRT на UDP и обратно, OBS Media Source не должен быть удалён или менять свои порты.

## 3. Синхронизация источников и звука

1. Включить экран и обе камеры. Отобразить на всех устройствах вспышку или LED тест, одновременно хлопнуть в ладоши.
2. Записать локальный вывод OBS и сравнить момент визуального события/аудиопика по кадрам.
3. На главной панели указать поправки видеокамер и аудио в миллисекундах. Проверить создание фильтров Render Delay и Audio Sync Offset.
4. Перезагрузить Local Broadcast и OBS. Калибровки должны сохраняться, автоматическая синхронизация — повторяться без ручного восстановления.
5. Повторить после изменения Wi-Fi условий и убедиться, что автоматическая сетeвая оценка не заменяет необходимую точную аппаратную калибровку.

## 4. Приёмочные критерии для перехода из Beta в Release

- 60 минут без незапланированного завершения или пропадания звука в OBS.
- Все три независимых источника стабильно видны в OBS, приём на 2–3 ПК.
- Измерены реальные p50/p95 задержки и потери на вашей конкретной сети.
- Звук презентера совпадает с его экраном без заметного дрейфа.
- Параметры после перезапуска компьютеров сохраняются, повторное обнаружение не требует ввода IP.
- Документирована точная калибровка камер; целевой допуск обсуждается после первого измерения.

## Автоматические тесты, доступные разработчику

```bash
go test ./...
go test -race ./...
go vet ./...
LB_TEST_MEDIA=1 go test -run TestSRT -v
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -o LocalBroadcast.exe .
```

**Отдельно**: в текущей Linux-среде нельзя физически проверить Windows WASAPI COM, реальную Wi-Fi задержку и OBS-сцены. Эти пункты обязательно выполнить на оборудовании.
